# T? "New VLM available" button

- **Goal:** UI tells the user when a newer frontier VLM than the configured one exists and offers to switch. Backs the pitch line "next year's model only improves the last-resort reader".
- **Files:** `sitelens/server.py` (new `GET /api/vlm` route), `web/src/` (badge/button), `CONTRACT.md` (document the route, PR).
- **Needs:** T20 (VLM backend registry).
- **Steps:**
  1. `GET /api/vlm` → `{current, latest, available: [...]}`. Gemini: list models via `GET /v1beta/models`, pick the newest `gemini-*-flash` (and pro). Cache 1 h. No key → `latest: null`.
  2. UI: small "New VLM: gemini-x.y-flash, update" button in the top bar when `latest != current`. Click → `POST /api/vlm {model}` switches the model for this server process (no `.env` write).
  3. Show the active VLM in the answer meta line for `vlm`/`facts`/`general` answers.
- **Done when:** with `SITELENS_GEMINI_MODEL=gemini-3.5-flash`, the button offers gemini-3.8-flash; clicking it makes the next VLM answer use 3.8.
- **Verify:** run the server with an old model, open :8000, click the button, ask a question that falls through to the VLM, check the trace.
